## 🔒 通用規則（每個任務都適用，執行前先確認遵守）

1. **只 add 要改的那個檔案**，絕不用 `git add .`；`git add` 後立刻 `git status` 確認變動的檔案跟預期一致，且沒有暫存/check資料夾被誤加入
2. **暫存/check資料夾一律建在 `D:\xian-shang-you-wei\scripts\` 底下**，絕對不要建在 `tools\` 或其他會被部署的路徑下
3. **main.py 修改一律用 bytes 層級操作**（`rb`/`wb`），明確用 `\r\n` CRLF 合併行，`old_str` 要精確比對後才 replace；改完立刻 `py_compile` 驗證語法正確
4. **改動前先 `view` 確認當前行號/內容**，不能沿用任何舊行號記錄（main.py 已經歷多輪編輯，行號會偏移）
5. **改動前先確認 git restore point**，並做本機物理備份
6. **批次修改多檔案（例如語言版本×N）**：先列清單說明「會改哪些檔案、為什麼」給我確認，再列出 dry-run 結果（會改N個、跳過N個），最後才實際寫入
7. **不要做一半就停下來問**——同性質的批次工作，要一次做完整批再回報結果，不要做3個就停下來問接下來要不要繼續
8. **任何「已修復/已存在/已完成」的宣稱，一律要實測驗證**（HTTP狀態碼、真實API回應、或直接截圖），不能只憑程式碼邏輯推論就說完成了
9. **改動涉及多個host共用同一份main.py時**，務必先查證host分流邏輯，不能用「無條件加header/邏輯」的寫法猜
10. **改主要判斷邏輯（分析引擎相關）一定要先回測**；純技術債/透明化修復（快取清除、轉址規則、文件生成）不算主邏輯，不需回測
11. **完成後**：commit message 要清楚寫明改了什麼、為什麼；push後到Zeabur確認部署狀態為「運作中」；能用claude-in-chrome實測正式環境的，一律實測，不要只看本機測試結果
